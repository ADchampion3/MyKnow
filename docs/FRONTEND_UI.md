# MyKnow 前端工作台
本轮处理进度和日志约定见 [`EMBEDDING_PROGRESS.md`](EMBEDDING_PROGRESS.md)：前端按 processing run 聚合显示 Embedding 进度，逐项失败通过分页明细查看；运行中的处理可以取消，失败/取消/缺失 chunk 可以一键重试。

当前 Web 工作台按 `MYKNOW_UI_REDESIGN_HANDOFF.md` 的视觉和信息架构实现：全局侧栏只负责模块导航，Wiki 目录属于 Wiki 工作区，引用、资料详情、检索运行和 Agent trace 按需使用右侧抽屉。

## 入口与模块

- `apps/web/app/layout.jsx` 加载全局工作台样式和 API 地址。
- `apps/web/app/page.jsx` 复用现有 API 请求、知识库上下文、Wiki 多页面、资料版本、检索、Agent 计划和任务状态。
- `apps/web/app/workspace.css` 保存原型确认的颜色、字体、间距、控件状态和响应式断点。

侧栏模块顺序为：知识库总览、资料库、Wiki、检索问答、待审核、任务与记录。真实数据只通过 API 加载；本地 UI 状态仅保存目录展开、当前页签、移动导航和抽屉状态。

## 本地验证

在空数据库或现有 `data/myknow.db` 上，从仓库根目录运行：

```powershell
npm install
npm run dev
```

打开 `http://localhost:3000/`。没有知识库时先创建知识库；进入 Wiki 后可创建多篇页面并通过父页面选择建立层级。资料导入、页面保存、恢复和 Agent 应用仍以服务端真实成功响应为准，原始资料和历史版本不会由前端删除或覆盖。

## 当前边界

- 视图切换目前是单页客户端状态，业务 API 和数据库路由不变；后续接入直接深链接时，应把知识库 ID 与 Wiki 页面 ID 纳入路由。
- Markdown 预览沿用当前项目的轻量预览函数；生产接入完整 Markdown 渲染器时需同时保留安全清理策略。
- 状态刷新继续采用现有轮询；这是本地 MVP 的 `ponytail` 上限，多用户实时协作时再升级为服务端推送。

## 批量上传

资料库的“添加原始资料”区域支持点击或拖拽一次选择多个 `.md`、`.txt`、`.pdf` 文件。文件先进入前端清单，用户确认后才开始上传；每个文件单独显示等待、上传中、处理中、处理成功、处理失败或格式不支持状态。

PDF 上传、追加版本和重处理都提供处理方式选择：自动 OCR（失败回退原生解析）、跳过 OCR（仅原生解析）或强制 OCR（失败即终止）。Markdown/TXT 始终跳过 OCR。上传接口返回“已入队”不代表材料处理成功；前端继续轮询资源和任务状态，直到显示最终结果，处理失败时同时显示服务端错误摘要。资源表中的处理状态也保留这一结果，页面刷新后仍可查看。

批次会复用现有 `POST /api/resources` 接口逐个创建资源，不新增批量数据库模型。每个文件带有稳定的 `Idempotency-Key`，提交失败项目可在同一清单中重试；已入队但处理失败的资源通过资源行的重试入口处理。批次部分失败时会保留成功结果并明确列出失败项。文件类型和大小仍以服务端校验为准，`accept` 属性只是选择器提示。

任务页按 processing run 提供“取消剩余任务”和“一键重试异常项”。取消只标记当前 run 的 embedding task，不删除原始文件、资源版本或已经成功的向量；一键重试只重新排队失败、取消或缺失的 chunk，成功 chunk 不会重复处理。解析阶段的资源任务则从资源行的“取消处理”入口取消。
