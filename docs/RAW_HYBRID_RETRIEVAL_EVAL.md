# Raw hybrid retrieval evaluation

The repository contains a standalone DeepEval/Vitest suite at
`evals/raw-hybrid-retrieval/`. It evaluates only the raw child chunk ranking
returned by `executeRetrieval()`; it does not evaluate answer generation or use
an LLM judge.

For the code-level data flow, see
[`RAW_HYBRID_RETRIEVAL_DATA_FLOW.md`](./RAW_HYBRID_RETRIEVAL_DATA_FLOW.md).

## Data contract

Put reviewed, versioned inputs in
`evals/raw-hybrid-retrieval/data/`:

- `corpus.json`: `raw-hybrid-eval-corpus-v1`, with stable child IDs and the
  resource/version/processing-run metadata needed to build an active fixture.
- `queries.json`: `raw-hybrid-eval-queries-v1`, with one-to-one stable query IDs
  and 1-256 Unicode code point queries.
- `qrels.json`: `raw-hybrid-eval-qrels-v1`, with one judgment per query and
  graded child-chunk judgments (`0`, `1`, `2`). Every query needs a positive
  grade and every judged chunk must exist in the corpus.
- `embedding-snapshot.json`: generated by the explicit preparation command.
- `manifest.json`: source archive/file hashes, conversion rules, split, counts,
  normalization impact, and output hashes. The archive and extracted originals
  are kept under the ignored `data/.source/` directory.

For the pinned public SciFact source, download, verify, safely extract, convert,
and validate all three inputs with:

```powershell
npm run eval:scifact:import
# use an already downloaded archive or another output directory when needed
npm run eval:scifact:import -- --archive=D:\downloads\scifact.zip --output-dir=D:\reviewed\scifact
```

The importer requires the pinned SHA-256, MD5, and byte count, rejects archive
path traversal and link entries, retains all 5,183 corpus documents, selects
the 300 queries referenced by the 339 test qrels, and publishes only after
cross-file validation succeeds. Re-running against the same archive is
content-deterministic; an existing differing output is left untouched.

The loader rejects duplicate IDs, malformed queries, unknown qrel targets,
empty positive sets, stale input hashes, provider/model/dimension mismatches,
duplicate vectors, non-finite vectors, and incomplete snapshots.

The fixture applies normal migrations and seeds an isolated SQLite database
with active resources, resource versions, indexed processing runs, raw child
chunks, parent context windows, the knowledge-base association, FTS projection,
and `retrieval_embeddings`. The runtime database is never opened for writes.

## Real embedding preparation

### 固定评测配置（`.env`）

评测命令和应用使用同一个根目录 `.env`。编辑一次模型、端点和超时即可，
之后通过 npm 指令重复运行；不要把 `EMBEDDING_API_KEY` 提交到仓库，密钥
继续从外部环境或凭据管理器提供：

```powershell
# 编辑 .env 一次，至少设置 EMBEDDING_MODEL
notepad .env
npm run eval:raw-hybrid:preflight:configured
npm run eval:raw-hybrid:prepare:configured
npm run eval:raw-hybrid:configured
```

预检可附加参数，例如：

```powershell
npm run eval:raw-hybrid:preflight:configured -- --sample-size=5
```

The real-provider path requires all of the following:

```text
EMBEDDING_PROVIDER=openai-compatible   # `openai` is also accepted
EMBEDDING_MODEL=<explicit-model-name>   # no mock default
EMBEDDING_DIMENSIONS=4096
EMBEDDING_API_BASE_URL=http://localhost:... or https://...
RETRIEVAL_VECTOR_ENABLED=true
RAW_HYBRID_EVAL_TIMEOUT_MS=1800000   # finite per-query limit; override for your service
RAW_HYBRID_EMBEDDING_TIMEOUT_MS=120000 # finite limit for each corpus/preflight request
```

`EMBEDDING_API_KEY` is optional for local compatible endpoints and remains an
environment-only secret. The endpoint must expose the OpenAI-compatible
`/embeddings` response shape. `AI_EGRESS_MODE=local_only` still permits a local
endpoint and blocks cloud endpoints.

Run a small real-provider preflight first (three corpus inputs by default):

```powershell
npm run eval:raw-hybrid:preflight
# choose another sample size
npm run eval:raw-hybrid:preflight -- --sample-size=5
```

The preflight checks the response shape, 4096-dimensional vector, provider
metadata, and the actual title-plus-content input. It does not write a
snapshot.

Prepare the complete corpus snapshot explicitly:

```powershell
npm run eval:raw-hybrid:prepare
# or use another data directory
npm run eval:raw-hybrid:prepare -- --data-dir=D:\path\to\reviewed-data
```

Preparation embeds every raw child chunk through the configured provider and
writes one validated JSON snapshot only after all vectors succeed. A provider
failure, invalid response, or dimension mismatch leaves an existing snapshot
unchanged and does not leave a partial replacement.

## Run the evaluation

```powershell
npm run eval:raw-hybrid
```

The runner writes live progress logs to stderr, including provider validation,
dataset and isolated-fixture setup, per-query retrieval/scoring progress, and
the final report path. Each line includes elapsed time and query position, so a
slow embedding request is distinguishable from a stalled run. The detailed
report remains on stdout and is also persisted atomically, which keeps the two
streams useful for separate terminal display or redirection.
The Vitest entry point does not apply its five-second default to the whole
dataset; `RAW_HYBRID_EVAL_TIMEOUT_MS` remains the finite timeout for each
query.

The command invokes DeepEval's TypeScript/Vitest integration. For every query
it creates an isolated migrated SQLite fixture, calls the real raw hybrid
orchestration with vector retrieval enabled, generates a live query embedding,
and fails if the production path degraded to keyword-only retrieval or found no
usable vectors. A missing provider, endpoint, model, snapshot, or compatible
manifest is a hard precondition failure; mock embeddings are never substituted.

The report printed to stdout contains per-query qrels, raw child chunk IDs,
public rank metadata (`rank`, `keywordRank`, `vectorRank`, `bm25Score`, `rrfScore`), metric
scores/reasons, and macro averages across queries. A successful run persists
`evals/raw-hybrid-retrieval/reports/scifact-raw-hybrid-report.json` atomically;
set `RAW_HYBRID_EVAL_REPORT_PATH` to choose another path. A failed run cannot
replace an existing report. The report also records the source/archive hash,
corpus/query/qrel/snapshot hashes, code commit plus working-tree hash, an
allowlisted provider configuration, timeout, metric gain, and qrel coverage.
The top-level `qrels` section records the judged query and judgment counts.

Reported metrics are Recall@K, Hit Rate@K, MRR@K, NDCG@K, and Judged@K for K=`1`, `3`, `5`,
and `10`. NDCG uses the BEIR/TREC linear gain (`grade`); Judged@K counts results
with an explicit qrel, including grade `0`, over the actual returned results.
A vacuous DeepEval threshold of `0` is used only so the Vitest
matcher can report scores; it is not a product-quality gate. No acceptance
threshold is imposed until real qrels and human expectations define one.

The first runner evaluates the combined hybrid path. Keyword-only and
vector-only ablations remain deferred diagnostics; multilingual and boundary
coverage are supplied by the reviewed query set rather than invented here.

## Clean-start workflow

1. Start from a clean checkout and run `npm install`.
2. Run `npm run eval:scifact:import` (or copy reviewed `corpus.json`,
   `queries.json`, `qrels.json`, and `manifest.json` into the evaluation data
   directory).
3. Configure the real embedding environment variables above.
4. Run `npm run eval:raw-hybrid:prepare`.
5. Run `npm run eval:raw-hybrid`; it writes the first successful report to the
   documented reports path. Set `RAW_HYBRID_EVAL_REPORT_PATH` to override it.

Offline metric and fixture tests run without cloud services:

```powershell
npm test
```

The test database is in-memory (or an explicitly supplied temporary SQLite
file), so the normal runtime SQLite file and its audit records are not mutated.

This baseline measures document-level SciFact raw-child retrieval after the
explicit conversion above. It is not a production chunking benchmark or a
business-quality guarantee.
